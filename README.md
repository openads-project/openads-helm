**Essential OpenADS Helm Charts**

This repository contains essential Helm charts for [***OpenADS***](https://openads-project.github.io/), the *Open Automated Driving Systems* project. Essential charts are those that do not directly belong to a specific OpenADService. In particular, the [openadservice](./charts/openadservice) chart provides a base structure and configuration for all dependent charts of specific OpenADServices, which are maintained in their respective repositories.

## 🚀 Usage

> [!NOTE]  
> Tested with Helm v3.19.0 and Helmfile v1.1.7.

Helm charts are stored as OCI artifacts in the GitHub Container Registry and can be installed directly from there.

```bash
helm show all oci://ghcr.io/openads-project/openads-helm/openadservice
helm template oci://ghcr.io/openads-project/openads-helm/openadservice
helm install openadservice oci://ghcr.io/openads-project/openads-helm/openadservice
helm uninstall openadservice
```

For OpenADServices, dedicated Helm charts are automatically generated by the [openads-dev-environment](https://github.com/openads-project/openads-dev-environment#helm-chart-generator), e.g., in [openads_demo_module](https://github.com/openads-project/openads_demo_module/blob/main/deployment/helm/Chart.yaml).

## Helmfile generator

[`utils/helmfile-generator`](./utils/helmfile-generator) converts a caller-owned Docker Compose project into a Helmfile directory. Project-specific Compose files, dotenv files, chart mappings, profiles, and runtime values remain in the caller repository.

[`helmfile-generator.yml`](./.github/workflows/helmfile-generator.yml) tests changes to the generator. [`helmfile-oci.yml`](./.github/workflows/helmfile-oci.yml) is a reusable workflow that checks out the caller with recursive submodules, generates the Helmfile, runs `helmfile build` and `helmfile template`, and packages the selected bundle. A caller can point validation at a parent Helmfile and package a wider bundle containing both generated and manually maintained releases.

Every successful call uploads the generated tarball as a seven-day GitHub Actions artifact. Pushes to the caller's default branch additionally publish the tags `<default-branch>` and `sha-<commit>` to `ghcr.io/<caller>/helmfile`; semantic version tags publish `vX.Y.Z` and `sha-<commit>`. SHA and version tags remain available until explicitly removed by a package cleanup policy.

```yaml
jobs:
  helmfile:
    permissions:
      contents: read
      packages: write
    uses: openads-project/openads-helm/.github/workflows/helmfile-oci.yml@<commit-sha>
    with:
      compose-file: docker-compose.yml
      env-file: .env
      chart-map: deployments/chart-map.yaml
      profiles: traffic,planning
      output-dir: deployments/generated
      helmfile-entrypoint: deployments/helmfile.yaml
      bundle-dir: deployments
      artifact-name: project-helmfile
```

`helmfile-entrypoint` defaults to `<output-dir>/helmfile.yaml`, and `bundle-dir` defaults to `output-dir`. The generated directory and entrypoint must be contained in the bundle. The workflow archives the bundle as-is.
